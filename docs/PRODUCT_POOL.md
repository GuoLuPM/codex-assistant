# 产品池合同（Codex 按需读取）

用户只提供文件、描述需要、勾选候选。Codex 负责分析与入库、检索计划、标签依据和生成 PPT；HTML 负责选择及临时只读分享，不提供编辑/上传/聊天入口。

历史选品通过 `sessions` 读取有界摘要，支持标题字面子串与状态过滤，使用创建时间和 ID 倒序的稳定排序；摘要不包含令牌、访问链接或商品快照。它不修改选择、不启动服务，也不代表原报价已重新核验。继续选品必须读取真实 `selection` 并遵守 open / sealed / closed 状态，详见 pool 短流程。

## 存储与边界

- `data/product-pool/` 为唯一私有池目录，SQLite 与原件快照均在其中。文件按 SHA-256 去重，同内容不同名不重复解析或覆盖；同名新内容是新来源版本，累计保存。
- 产品身份是来源内容哈希 + 记录定位；不同来源的同名产品保留独立报价，只有核对品牌、型号和规格后才允许分组展示，不删除报价记录。可从一个文件分批加入单品；同定位同内容重试无副作用，同定位内容冲突显式拒绝。
- 原始事实、报价角色、来源证据与推荐判断分层。没有价格/图片也能入库；未知价格不等于 0。检索必须指定预算价格口径。
- 推荐标签开放 kind/value，不把节日、厂家写成代码规则。标签带 `source` 或 `inferred`、理由和产品证据；“适合新年送同事”由 Codex 转成价格/类目/标签检索。无标签不等于不适合，需有界补看候选再添加有依据的判断。
- 候选页是冻结会话：产品快照、展示价格、顺序均固定，选择单独保存在 SQLite；仅在本机 loopback 服务保存勾选。PPT 只消费该会话已选 ID，核对产品、来源和图片后复用既有生成器。
- 分享先复核候选，再显式投影商品名称、型号、规格、说明、展示价和合规图片到独立只读服务；不向它传数据库连接、本机选择令牌、来源文件名、证据、标签或勾选结果。分享有效期和选择封存相互独立，主动关闭会话则撤销分享。合同及边界见 [临时分享](TEMPORARY_SHARING.md)。

### 数据关系

| 对象 | 身份与职责 |
| --- | --- |
| pool_documents / pool_aliases | 内容哈希唯一；保留原件相对路径、曾用文件名与 pending/partial/ready 状态 |
| products / prices / products_fts | 复用已有事实、按价格角色索引与全文检索；不在模型上下文传递全库 |
| pool_members | 产品与原件、稳定记录位置关联；同来源同位置唯一，内容冲突拒绝覆盖 |
| pool_evidence / pool_observations | 原生提取缓存由数据库管理；视觉转录单独保存观察人和图片位置，不能冒充原生文字 |
| pool_tags | 可扩展推荐维度，按 kind/value/origin 索引；依据和理由与商品事实分开 |
| pool_profiles / pool_metadata / pool_events | 版本化的检索资料及变更历史；逐产品验证原文，保留推断标记；撤销补充字段不改原始记录 |
| pool_vocabulary | 当前池的等价叫法；不把品牌/场景规则硬编码在解析器 |
| pool_source_state / pool_offer_terms | 明确的报价系列、原文日期、有效状态及单个价格的币种/单位/税运费/起订量；未知保持未知 |
| pool_product_links | 经核对的同款报价关系，可分页查看全部；身份资料变更时解除并提示复核 |
| pool_sessions / pool_choices | 冻结候选事实、价格和推荐/报价上下文，保存勾选及修订号；拒绝跨会话 ID、旧修订、空导出及变化或撤回的报价 |

原件放 `objects/<SHA256>/`，图片放 `assets/`，选择页放 `sessions/<ID>/`，数据库是 `catalog.sqlite3`。原件和资源使用相对路径；搬迁整个池时产品 ID 不变。源文件在外部被删除也不影响快照。不要手改数据库或缓存；原件/图片校验失败会明确停止。正式池只允许主代理通过工具写入；原始报价更正应加入新的来源版本。

### 格式与语义边界

XLSX 复用坐标映射和真实图片抽取；PDF/PPTX 提取原生文字与图片；DOCX 读取段落/表格；CSV（UTF-8 逗号分隔）、TXT/MD、XLS 读取文字/单元格；图片与扫描页可显式视觉转录。DOCX 嵌入图片、旧 DOC 和其他不支持格式需明确转换或补充原图，不能声称已完整自动支持。

来源引用证明文本确实存在，不能自动证明模型关联对了商品、价目和图片。Codex 仍须核对语义；预算使用明确价格角色，未知/无法解析的价格不进入数值范围匹配。非 XLSX 分批导入保持 partial，不能把已抽取几款说成整个文件完成。

`category` 检索同时支持规范资料、原始品类及 `kind=category` 的派生层级，例如 `个护/护手霜` 可被 `--category 个护` 命中；补充资料不改写原始字段。抽象场景由 Codex 区分硬条件与偏好，`retrieve` 统一执行有界补查、融合及去重。标签覆盖不足时加入品类/文字路线，不能将零标签命中当作无合适商品。原始列没有映射成显示说明时，也进入候选事实摘要；长说明按需读取，不能将未展示视为缺失。

资料、交易条件、源版本、检索计划、撤销和历史的完整合同见 [POOL_RETRIEVAL.md](POOL_RETRIEVAL.md)。新旧数据库使用附加表兼容，旧选择会话保留；不整量重建池或重写价格。单次补查的全文候选有上限，覆盖提示不是召回率证明。

## 路线依据

采用内容寻址原件与 SQLite 唯一约束/事务，参考 [Git 内容寻址对象](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)、[SQLite UPSERT](https://sqlite.org/lang_upsert.html) 和 [事务](https://sqlite.org/lang_transaction.html)。摘要不是近似商品去重；事务不允许半批入库。

参考 product-brain 的文件指纹、来源定位和证据留存；不引入它的独立模型路由、并行抽取服务、固定进货价准入或价格高低推断。字段语义与场景理解交给当前 Codex，工具只执行可核验合同。

## 交付与验收

一份交互 HTML 是任务过程界面，最终仍只交付一份 PPT。验证覆盖改名重复文件、增量加入、同定位冲突、事务回滚、失真证据、标签来源区分、选择持久化、跨会话隔离、选中内容与 PPT 一致。模型验收使用相同口语化任务，Luna 可失败；Terra/Sol 的结果以数据库与实际文件检查为准，不采信口头完成。

### 既有选择页与入库验证（2026-09-29）

- 41 项自动测试通过；Edge/Playwright 检查桌面、窄屏、真实原图、勾选保存、刷新恢复、仅选择交互及局部 DOM 更新。实际选择第二款后生成一页 PPT，核对名称、原价格及未选项排除；客户旧成品哈希保持不变。
- 本机试验池包含 12 个唯一来源、2,528 条产品；新增 PDF/PPTX 各抽取 2 款，两个来源均如实标为 partial。场景标签当前仅覆盖样例商品，不能宣称全量语义标注完成。
- 在该数据规模复用数据库连接，价格 + 品类 + 两个标签组合查询 30 次的中位数约 1.62 ms；不包含启动 Python、Codex 思考、首次解析和 PPT 生成，不能当作端到端时长保证。

模型实验入口 `scripts/evaluate_pool_models.py --codex <本机Codex可执行文件> --work-dir <空的私有目录>`，不在生产或 CI 调用。普通速度 `service_tier=default`、medium 推理；每个模型独立数据库。四项同题：改名重复文件、带文档指令干扰的单品入库、口语场景/预算到候选、用户选择到准确 PPT 数据。

| 模型 | 明确合同后的首次通过 | 最多一次实际校验反馈后 |
| --- | --- | --- |
| GPT-6 Sol | 4/4 | 4/4（无需反馈） |
| GPT-5.6 Terra | 4/4 | 4/4（无需反馈） |
| GPT-6 Luna | 2/4 | 4/4 |

初轮实验暴露了标签 ID/引用结构及测试字段“渲染”歧义；统一明确为产品 ID、逐字来源值、`export_ppt_before_selection` 后，对三个模型同样复测，没有降低数据校验或增加样例专用规则。Luna 仍出现文件名去重和不属于该商品的标签证据，校验反馈能促成修正；默认不让它独立提交正式库。

此次独立 CLI 代理执行本地工具受到执行策略拒绝；以上成绩是**模型输出决策 JSON，主控制器在真实隔离数据库执行**，不等于已证明独立代理可管理本机终端。四个小样本也不代表各种未来文件全部通过。日常模型分工按 [正常 / 低消耗两档](AGENT_WORKFLOW.md) 执行；本节成绩仅对应已记录的具体模型，不因用户选档或模型升级而改变。正式写入必须经过工具校验。

### 检索增强验收（2026-09-29）

- 56 项自动测试通过，包括证据所属产品、单位换算、旧版本冲突、原子回滚、价格口径分离、同日/未知日期、部分导入、同款报价分页、交易条件和新旧会话兼容。独立普通速度 Sol 审查后补齐起订量语境和同款报价后续读取。
- 对同一 2,528 条原始记录补充资料后，缺分类从 1,213 降为 27，缺品牌从 2,327 降为 470。拦下 4 条不属于对应产品原文的证据，并人工排除 6 条混合品牌礼盒的单品牌推断。补充分类仍标记 inferred，不能据此宣称原始解析或全量归类百分之百正确。
- 真实池对照：一项原先为零的品牌结构化查询现命中 915 条；食品父类从 0 到 343 条；百元内某日常品名的等价叫法补查从 1 到 10 条。它们是对照查询数量，不是整个库的召回率。
- 三类实际检索计划各运行 10 次，共 30 次；本机复用连接中位数 261 ms，最大 471 ms。包含多路查询/合并/全池质量提示，不包含首次整理、进程启动、Codex 推理和 PPT 生成，与先前单条 SQL 测量不同。
- 产品数量、原始产品/报价/来源记录、已保存选择、客户现有 PPT 均核对未变；SQLite integrity/foreign-key 检查通过。12 份来源仍缺少足以确定报价系列与日期的资料，2 份来源只部分导入，供应商字段仍未知；没有填猜测值来消除缺失。

新的可选实验：`scripts/evaluate_pool_retrieval.py --codex <路径> --work-dir <空的私有目录>`。八类口语需求：节日礼盒、同义词与软偏好、排除食品/数码、半升容量、混装低糖食品、静音资料缺失、最新版不确定及确定最新版。普通速度，独立合成数据库，计划与后续选择均由模型给出，由控制器执行并检查。

| 模型 | 修复摘要链路后的首次 | 一次真实校验反馈后 |
| --- | --- | --- |
| GPT-6 Sol | 8/8 | 无需反馈 |
| GPT-5.6 Terra | 5/8 | 8/8 |

最初实验发现未映射原始列被候选摘要遗漏，修复通用证据投影后重测；没有给模型预选 ID。Terra 曾把“实物”误解为必须有图片，以及把包装要求过度限定为单个品类。使用 `--feedback-from 上次私有实验目录` 可复现最多一次恢复；不降预算、规格或证据门槛。此结果支持 Sol 负责计划、Terra 负责有校验反馈的有限工作，不证明弱模型可以无人核对地处理所有新文件。

### 可靠性复核（2026-09-30）

- 重跑普通速度 GPT-6 Sol 的八类口语检索实验，首次 8/8 通过；仍是模型决策、控制器执行的合成样本实验，不是任意资料或独立终端操作的保证。两个评测入口现在以非零退出码报告模型错误、校验失败及不完整结果。指定的 Codex CLI 必须支持隔离配置参数 `--ignore-user-config` / `--strict-config`；不支持时应选用兼容版本，不删除隔离参数来绕过。
- 实际池 2,528 条记录、12 份原件的哈希及 SQLite 完整性/外键检查通过；已入库 XLSX 的工作表均有记录或显式忽略映射。新增测试修复了自动模式跳过未识别工作表仍标 ready 的问题：现在返回 needs_mapping，明确核对覆盖后才提交整份；不按品牌或表名添加例外。
- 三组实际查询各执行三次，复用连接的中位数约 133—291ms，含多路补查与覆盖提示，不含 Codex 推理、Python 启动或 PPT。两组返回有界候选；一组容量硬条件查询为零，不能当成库内没有相应商品。规格未结构化时，Codex 要读取候选原文，按证据补充属性后用原硬条件重查。
- 实际 PDF 读取及合成商品 PPT 导出再次通过。库中仍有 27 款缺分类、470 款缺品牌、全部 12 份来源缺少核实后的报价版本，场景标签只覆盖 2 款，2 份来源仍为部分导入。这些是资料覆盖限制，不用猜值补齐。
- 当前适合 Codex 驱动、单机维护、用户勾选的日常业务。更大数据规模、多人同时写入、跨设备无人值守同步，以及备份恢复和安装包升级的自动化，尚无完整交付保证；不同新电脑仍需按部署检查实际验收。
