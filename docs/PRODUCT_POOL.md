# 产品池合同（Codex 按需读取）

用户只提供文件、描述需要、勾选候选。Codex 负责分析与入库、检索计划、标签依据和生成 PPT；HTML 只负责选择，不提供编辑/上传/聊天入口。

## 存储与边界

- `data/product-pool/` 为唯一私有池目录，SQLite 与原件快照均在其中。文件按 SHA-256 去重，同内容不同名不重复解析或覆盖；同名新内容是新来源版本，累计保存。
- 产品身份是来源内容哈希 + 记录定位；不同来源的同名产品保留报价版本，禁止猜测实体合并。可从一个文件分批加入单品；同定位同内容重试无副作用，同定位内容冲突显式拒绝。
- 原始事实、报价角色、来源证据与推荐判断分层。没有价格/图片也能入库；未知价格不等于 0。检索必须指定预算价格口径。
- 推荐标签开放 kind/value，不把节日、厂家写成代码规则。标签带 `source` 或 `inferred`、理由和产品证据；“适合新年送同事”由 Codex 转成价格/类目/标签检索。无标签不等于不适合，需有界补看候选再添加有依据的判断。
- 候选页是冻结会话：产品快照、展示价格、顺序均固定，选择单独保存在 SQLite；仅在本机 loopback 服务保存勾选。PPT 只消费该会话已选 ID，核对产品、来源和图片后复用既有生成器。

### 数据关系

| 对象 | 身份与职责 |
| --- | --- |
| pool_documents / pool_aliases | 内容哈希唯一；保留原件相对路径、曾用文件名与 pending/partial/ready 状态 |
| products / prices / products_fts | 复用已有事实、按价格角色索引与全文检索；不在模型上下文传递全库 |
| pool_members | 产品与原件、稳定记录位置关联；同来源同位置唯一，内容冲突拒绝覆盖 |
| pool_evidence / pool_observations | 原生提取缓存由数据库管理；视觉转录单独保存观察人和图片位置，不能冒充原生文字 |
| pool_tags | 可扩展推荐维度，按 kind/value/origin 索引；依据和理由与商品事实分开 |
| pool_sessions / pool_choices | 冻结候选事实和价格，保存勾选及修订号；拒绝跨会话 ID、旧修订、空导出和已关闭会话 |

原件放 `objects/<SHA256>/`，图片放 `assets/`，选择页放 `sessions/<ID>/`，数据库是 `catalog.sqlite3`。原件和资源使用相对路径；搬迁整个池时产品 ID 不变。源文件在外部被删除也不影响快照。不要手改数据库或缓存；原件/图片校验失败会明确停止。正式池只允许主代理通过工具写入；原始报价更正应加入新的来源版本。

### 格式与语义边界

XLSX 复用坐标映射和真实图片抽取；PDF/PPTX 提取原生文字与图片；DOCX 读取段落/表格；CSV（UTF-8 逗号分隔）、TXT/MD、XLS 读取文字/单元格；图片与扫描页可显式视觉转录。DOCX 嵌入图片、旧 DOC 和其他不支持格式需明确转换或补充原图，不能声称已完整自动支持。

来源引用证明文本确实存在，不能自动证明模型关联对了商品、价目和图片。Codex 仍须核对语义；预算使用明确价格角色，未知/无法解析的价格不进入数值范围匹配。非 XLSX 分批导入保持 partial，不能把已抽取几款说成整个文件完成。

`category` 检索同时支持原始品类及 `kind=category` 的派生层级，例如 `个护/护手霜` 可被 `--category 个护` 命中；派生标签不改写原始字段。抽象场景由 Codex 规划多个有界查询，合并 ID 后核对。标签覆盖不足时先收窄价格/品类并查看少量原文，再补有依据的标签供下次复用；不要求全库提前调用模型，不将零标签命中当作全库无合适产品。

## 路线依据

采用内容寻址原件与 SQLite 唯一约束/事务，参考 [Git 内容寻址对象](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)、[SQLite UPSERT](https://sqlite.org/lang_upsert.html) 和 [事务](https://sqlite.org/lang_transaction.html)。摘要不是近似商品去重；事务不允许半批入库。

参考 product-brain 的文件指纹、来源定位和证据留存；不引入它的独立模型路由、并行抽取服务、固定进货价准入或价格高低推断。字段语义与场景理解交给当前 Codex，工具只执行可核验合同。

## 交付与验收

一份交互 HTML 是任务过程界面，最终仍只交付一份 PPT。验证覆盖改名重复文件、增量加入、同定位冲突、事务回滚、失真证据、标签来源区分、选择持久化、跨会话隔离、选中内容与 PPT 一致。模型验收使用相同口语化任务，Luna 可失败；Terra/Sol 的结果以数据库与实际文件检查为准，不采信口头完成。

### 本轮验证（2026-09-29）

- 41 项自动测试通过；Edge/Playwright 检查桌面、窄屏、真实原图、勾选保存、刷新恢复、仅选择交互及局部 DOM 更新。实际选择第二款后生成一页 PPT，核对名称、原价格及未选项排除；客户旧成品哈希保持不变。
- 本机试验池包含 12 个唯一来源、2,528 条产品；新增 PDF/PPTX 各抽取 2 款，两个来源均如实标为 partial。场景标签当前仅覆盖样例商品，不能宣称全量语义标注完成。
- 在该数据规模复用数据库连接，价格 + 品类 + 两个标签组合查询 30 次的中位数约 1.62 ms；不包含启动 Python、Codex 思考、首次解析和 PPT 生成，不能当作端到端时长保证。

模型实验入口 `scripts/evaluate_pool_models.py --codex <本机Codex可执行文件> --work-dir <空的私有目录>`，不在生产或 CI 调用。普通速度 `service_tier=default`、medium 推理；每个模型独立数据库。四项同题：改名重复文件、带文档指令干扰的单品入库、口语场景/预算到候选、用户选择到准确 PPT 数据。

| 模型 | 明确合同后的首次通过 | 最多一次实际校验反馈后 |
| --- | --- | --- |
| GPT-6 Sol | 4/4 | 4/4（无需反馈） |
| GPT-5.6 Terra | 4/4 | 4/4（无需反馈） |
| GPT-6 Luna | 2/4 | 4/4 |

初轮实验暴露了标签 ID/引用结构及测试字段“渲染”歧义；统一明确为产品 ID、逐字来源值、`export_ppt_before_selection` 后，对三个模型同样复测，没有降低数据校验或增加样例专用规则。Luna 仍出现文件名去重和不属于该商品的标签证据，校验反馈能促成修正；默认不让它独立提交正式库。

此次独立 CLI 代理执行本地工具受到执行策略拒绝；以上成绩是**模型输出决策 JSON，主控制器在真实隔离数据库执行**，不等于已证明独立代理可管理本机终端。四个小样本也不代表各种未来文件全部通过。Sol 作为默认，Terra 用于合同明确的操作/核对，复杂未知结构仍交 Sol；正式写入必须经过工具校验。
